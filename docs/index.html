k8s-lab

A four-node Kubernetes cluster that builds itself from code. Terraform creates the platform, Argo CD deploys the workloads from Git, and an Azure DevOps pipeline proves the whole thing works and then deletes it.

Architecture

One command builds everything

Terraform talks to Docker to create the kind cluster, then installs the platform with Helm. Argo CD is the last piece Terraform installs. After that, Git drives the workloads.

Ownership

Platform in Terraform, workloads in Git

Each thing has exactly one owner, so a change always has one obvious place to go.

Terraform

The platform, built once per environment.

  • kind cluster: 1 control-plane, a variable number of workers, digest-pinned node image
  • Cilium as CNI, with the default CNI disabled; a variable falls back to kindnet
  • Traefik on the control-plane node, published on hostPorts 28080 and 28443
  • metrics-server with --kubelet-insecure-tls
  • Argo CD at argocd.localtest.me
  • One Argo CD Application, through the argocd-apps chart

Git

The workloads, changed by pull request.

  • charts/hello: Deployment, Service and Ingress for the demo app
  • Argo CD syncs it automatically, prunes removed resources and reverts manual drift
  • The Ingress uses the traefik class and answers at hello.localhost

The hand-off. Terraform does not deploy hello. It creates one Application that points Argo CD at the repository. From that moment, a commit to charts/hello is the only way hello changes.

CI / CD

Prove it on every commit

The Azure DevOps pipeline builds the full lab on a throwaway cluster, checks it, and always tears it down.

  1. install terraform
  2. init
  3. fmt -check
  4. validate
  5. apply
  6. smoke test
  7. destroy (always)
  • The smoke test waits for all nodes Ready, the Argo CD Application Healthy and Synced, then requests hello and Argo CD through Traefik.
  • Runs on a Microsoft-hosted ubuntu-latest agent with Docker preinstalled. No service connections, no cloud resources, no cost.
  • condition: always() on destroy removes the cluster even when an earlier step fails or the run is cancelled.

Engineering notes

Decisions and problems solved

Traefik instead of ingress-nginx

ingress-nginx is retired upstream. Traefik takes its place as the default IngressClass, pinned to the control-plane node with hostPorts because kind has no load balancer.

Cilium native routing

In the default tunnel mode, pods could not reach other nodes' IP addresses, so metrics-server could not talk to the API server and crash-looped. Cilium now uses native routing across the shared Docker bridge, with the pod CIDR set so node-bound traffic is masqueraded.

CNI-aware cluster creation

With Cilium the cluster is created with disable_default_cni and without waiting for Ready, because nodes only become Ready once the CNI is installed. A variable switches back to kindnet.

Uncommon host ports

Traefik is published on 28080 and 28443 so the lab never collides with other local services. Both are Terraform variables.

Helm provider pinned to 2.x

Version 3 changed the provider block syntax. Pinning ~> 2.17 keeps the configuration stable and reproducible, and the lock file is committed.
